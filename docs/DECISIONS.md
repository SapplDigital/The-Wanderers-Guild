# Decisions

Short log. Newest at the bottom. Format: date — decision — why.

- 2026-09-28 — **GDScript**, not C#. — No build step, works with the godot MCP, simple headless tests. Revisit only if performance-heavy systems need it.
- 2026-09-28 — **Pixel pipeline = SubViewportContainer with `stretch_shrink` (default 3 → 640×360) + nearest upscale + posterize/Bayer-dither shader.** UI renders at native res above it. — Standard low-res 3D approach; UI text stays readable; shrink is tunable per display.
- 2026-09-28 — **Perspective camera, FOV 40**, not orthographic. — Distant landmarks (the core "what's that?" hook) need perspective depth. Cost: some texel shimmer while rotating; accepted after the spike.
- 2026-09-28 — **Visual spike passed; pixel-art-3D direction approved by the user.** No low-poly fallback.
- 2026-09-28 — Cinematics: Camera3D is top_level and blends between the gameplay anchor and any `Node3D` pose (`play_cinematic(pose, fov)` / `end_cinematic(adopt_view, return_zoom)`). — Any scripted tween/animation can drive a pose; the return blend is automatic.
- 2026-09-28 — Textures are procedural (NoiseTexture2D with palette gradients) until the art direction is locked. — No asset production before the spike is validated (GDD 19.3).
- 2026-09-28 — **Camera states NORMAL / LOOK / CINEMATIC.** NORMAL and LOOK are one continuous zoom rail, not modes: zooming in lowers pitch (-55° far → -8° near), raises the pivot to shoulder height and shifts the frame (v_offset) so the player sits low and the horizon fills the view. Mouse/stick pitch offset (±25°) rides on top; absolute limits -75°..+10°. — Looking at the horizon is a scroll-wheel away and never feels like a separate mode.
- 2026-09-28 — **`CinematicReveal` (Area3D + Marker3D path + focus).** Starts at the current camera pose (no cut), glides through markers while slerping toward the focus, widens FOV, holds, then returns with yaw AND pitch adopted on the LOOK end of the rail. Player input is locked only during the ~5 s reveal. — The revealed thing is still in frame when control returns; that's the moment the player decides to go there.
- 2026-09-28 — **Landmark readability = thin exponential fog (0.0025) + height fog (below 4 m).** — Ground clutter fades into mist while tall silhouettes stay readable at 300 m+. Composition rule from the camera test: the hero silhouette must stand against open sky, not overlap nearer landmarks or mountains.
- 2026-09-28 — **Slice region layout:** village south, forest north, path → overlook hill → reachable ruin; floating island + giant tree + mountains as unreachable horizon landmarks. Every stop has a reason: village LOOK shows the ruin above the treeline, the camp's trail stones point to the hidden hollow, the overlook reveal frames the island with the ruin as the next reachable goal. — Pull the player forward with sightlines, not waypoints (GDD 7).
- 2026-09-28 — Blockout geometry is instanced prop scenes + generated `.tscn` (generator was a one-off); edit the scene in the editor from now on. Hill collision via `trimesh_collision.gd`.
- 2026-09-28 — **World memory = `GameState` autoload with flat string flags** (`discovered.*`, `<id>.used`, `world.*`; later `npc.*`, `quest.*`, `event.*`) + `flag_changed` signal. — The event director (M10) will read prerequisites from and write consequences to the same store; save/load (M12) is just this dictionary. No schema until data files start writing keys.
- 2026-09-28 — **Interaction building blocks:** `Interactable` (verb, persistent id, one-shot, message / repeat / flag-conditional message, sets a flag, emits `interacted`), `Interactor` on the player (nearest usable in reach), `DiscoveryZone` (first entry → flag + place-name card), `StateToggle` (show/hide world pieces from a flag). Messages are a stopgap until dialogue (M8) takes over longer text.
- 2026-09-28 — **HUD renders inside the 640×360 pixel viewport** (pixel-consistent, upscaled with the world). Prompt is anchored to the focused object, not a fixed screen slot. Grayscale font AA at 10 px: no-AA 8 px kerned badly ("old" read as "ald"). No quest markers; compass shows cardinals only.

## Atmosphere pass (2026-09-28)

- **Audio = event names, not files.** Gameplay calls `AudioManager.play(&"discovery")`, `play_at(&"interact", node)`; `data/audio/sound_bank.tres` maps each event to stream(s), bus, volume, pitch variance, loop, 3D range. Replacing a sound = editing the bank. Scene pieces: `SoundEmitter` (looping world sound, follows visibility so StateToggles silence it), `AmbienceZone` (layered beds, last-entered wins, 2.5 s crossfade), `SurfaceArea` + `Footsteps` (dirt/wood/grass by area under the feet). Buses Music/Ambience/SFX/UI created at startup; volumes saved in user://audio.cfg.
- Placeholder sounds generated with ElevenLabs; source files had wildly different levels (forest bed -74 dB mean, combat bed -12 dB), so all files are peak-normalised and **the mix lives in the bank's volume_db**. OGG instead of MP3 so loops are gapless.
- One-shots are added deferred with autoplay: `play_at` during scene setup (e.g. a discovery on spawn) used to fail with "parent busy".
- **Tree crowns fade near the camera** with StandardMaterial3D's built-in pixel-dither distance fade (3–7 m). Native feature, dithered look fits the pixel style; replaces the planned custom occluder shader for now. Does not handle crowns >7 m between camera and player (rare at LOOK zoom).
- Prompt glyph follows the last used device, read from the InputMap (layout-correct key names; Xbox labels on pad).
- Interaction feedback: UI tick + world sound at the object + player turns toward it and leans in + prompt pulse.
- Wisps sit 2.1 m high and alternate 1.5 m either side of the trail: at chest height in the gap they covered the player.

## Milestone 6: world-space combat migration (2026-09-28)

The earlier grid prototype is obsolete. The GDD's world-space combat design is authoritative: positions and distances are continuous, and the actual clearing supplies obstacles, cover, terrain and elevation. Do not restore `CombatGrid`, cell coordinates, grid overlays or grid-based UI.

- **Rules vs presentation split.** `CombatSpace` and `CombatState` are testable rules; commands return events which `CombatController` plays back. `CombatArea` scans scene collision and surface data. `TacticalOverlay` draws temporary rings, paths and attack lines only while choosing. `CombatUnit.position` is a `Vector3`; movement plans are distance based and route around obstacles.
- **Tactical factors:** line of sight, partial cover, terrain cost/defense, height advantage, engagement zones and opportunity attacks are handled in the shared world-space rules. HUD language explains range, cover and blocked sight in metres and plain words.
- **Encounter design:** enemies are visible before combat; entering the trigger engages, while walking around preserves the option to avoid the encounter. Victory persists the cleared flag; defeat returns the player to the clearing edge. Exploration health carries into and out of combat.
- **Verification status:** `tests/test_combat_rules.gd` was migrated to world-space cases and checks the combat scripts for grid remnants. Run it and validate the actual scene in Godot before treating this migration as complete; the current handoff environment has no Godot executable/MCP available.

## Pre-M7 design audit (2026-09-28)

- The game is an exploration RPG first. Combat is optional when the encounter fiction allows it; preserve bypass, investigation, negotiation and retreat as future encounter outcomes.
- Treat enemies as behavior/data profiles rather than assuming all hostile entities are conventional combatants. The three slice archetypes are examples, not an exhaustive model; allow passive, fleeing, territorial, negotiable and world-scale entities later.
- Do not introduce traditional classes, levels or numerical progression inflation before the core loop proves a need. Keep progression open to equipment, abilities, discoveries, relationships, guild growth and player choices.
- Environmental rules should follow visible physical causes. Keep the tactical overlay temporary and modest; do not convert every prop into a bonus.
- The revised GDD and master prompt now use the exploration-first genre and add the audit's slice success criteria. M7 stays gated until the migration and integration are verified.

## M7 AI dispatcher (2026-09-28)

- **Data chooses the brain; profile labels do not dispatch behavior.** `ActorData.ai_profile` is readable encounter data, while `ActorData.ai_brain` names a `CombatBrain` script. `BrainDispatcher` creates that script and sends only its intent dictionaries to `CombatState`, which continues to validate movement and ability use. Adding passive, fleeing, defensive, territorial, social, negotiable, environmental or unusual creatures requires a data/script choice, not a dispatcher edit.
- **Three demonstration strategies:** `MeleeBeastBrain` approaches a vulnerable foe; `RangedUtilityBrain` samples legal firing positions and values target exposure, cover and terrain; `GuardianBrain` declares a generic visible intent before its heavy strike. The declaration is transient AI state on `CombatUnit.brain_memory`; combat rules do not interpret it.

## M8 dialogue (2026-09-28)

- **Data = Godot Resources with typed sub-resources** (`scripts/dialogue/data/`, instances in `data/dialogue/`): `DialogueData` (id, `entries`, `nodes`) → `DialogueNode` (id, speaker, text, `choices`, `next`) → `DialogueChoice` (text, `conditions`, `consequences`, `next`; empty `next` ends the conversation) → `DialogueCondition` / `DialogueConsequence`. Inspector-editable, one data style with the rest of the project.
- **Entries pick the opening.** `entries` are choices the runner picks automatically: the first whose conditions pass (e.g. first meeting vs. revisit). Their consequences run on start, so "met" is plain data, not code.
- **Conditions and consequences are GameState flags only:** `IS_SET`, `NOT_SET`, `EQUALS` (string compare). Consequences: `SET_FLAG` (empty value = true) or `EVENT` (a named trigger). No expression language, no dice checks; add checks when a quest needs one.
- **Event triggers without a manager.** `DialogueRunner` emits `event_fired(id)`; `DialogueTrigger` re-emits it and broadcasts `call_group("dialogue_events", "on_dialogue_event", id)`, so M9 quests / M10 events can listen without dialogue knowing them. No DialogueManager autoload (no god object); add one only if a later milestone needs a global entry point.
- **Pure runner, thin presentation.** `DialogueRunner` (RefCounted, flag store injected) holds all branching; `DialogueUI` only shows speaker/text/choices and forwards picks; `DialogueTrigger` listens to an unchanged `Interactable.interacted`. Validator (`DialogueData.validate()`) rejects missing entries, duplicate/broken ids, unreachable nodes, and nodes whose choices are all conditional (possible soft-lock).
- **UI:** compact bottom panel in the 640x360 pixel layer. Selection is shown with a `>` marker, not colour. Up/down (W/S, arrows, stick, D-pad) moves, the interact button (F / A) confirms, the leave button (Esc / B) walks away with no consequences; mouse hover/click works too. Prompt glyphs follow the last-used device via `InputGlyphs`. The player can't move while talking.
- **Proof NPC: Wenna the well-keeper** beside the village well. First meeting vs. revisit, a rumour choice that fires `rumour.old_wood_lights`, a choice that lights the well lamp (`world.well_lamp_lit` → `StateToggle`), and an extra line once `world.shrine_awakened` is set. Placeholder lines, to be replaced when `docs/story/` exists. Existing `Interactable` messages stay as they are.
- **Player-experience audit (renders, 2026-09-28):** Wenna reads as a person at the well, and "F Talk" appears when you walk up. The panel takes the bottom third and leaves the plaza visible; the speaker name is warm orange, and the selected reply has a `>` plus brighter text. Glyphs switch with the device ("F Choose / Escape Leave" ↔ "A Continue / B Leave"). Lighting the lamp is visible right away: a lamp on a bracket off the well post (moved out from under the roof after the first render hid it) and warm light on the well. After a world reload she opens with the lamp line and the lamp stays lit. Weak spots: placeholder capsule body; the unlit lamp is dark on dark (fine for "the lamp is dark"); the keyboard glyph reads "Escape" rather than "Esc".

## M9 quest: The Missing Ring (2026-09-28)

- **Quest state is GameState flags only; no QuestManager autoload.** `QuestData` (`scripts/quests/data/`, instances in `data/quests/`) describes the quest; `QuestTracker` is pure and read-only (flags in, status out: active, current objective, outcome). Dialogue replies, interactions and combat victories write the flags. Save/load (M12) needs nothing extra.
- **Objectives are derived from world facts, not a forced sequence.** The current objective is the first one whose `done_when` fails, so any route that makes a fact true completes it. Taking the ring by either route also sets "knows where the hoard is", and the owner accepts the ring even if the quest was never accepted. Conditions reuse `DialogueCondition` (all must pass); where two routes lead to the same fact, both write the same flag instead of adding OR logic.
- **Items stay flags in M9** (`quest.missing_ring.has_glint_stone`, `.has_ring`). Minimal inventory is in the backlog.
- **Routes:** learn about the hoard from Wenna or by finding it at the midge stones (hoard sits outside the 7 m trigger). Get the ring by winning the existing midge fight (`encounter.forest_edge_midges.cleared`) and searching the hoard, or by trading Wenna's glint stone at the hoard; the midges then stay an optional encounter. No combat code changed.
- **Outcomes:** return the ring (`.returned` → a lantern appears by the owner's door) or keep it (`.kept` → a "LOST: RING" notice on the board and on reading it; Wenna remarks on it). Placeholder names/lines until `docs/story/` exists.
- **NPCs share `scenes/npcs/villager.tscn`**; the conversation is set per instance. The hoard is a speaker-less conversation on an `Interactable`, so objects can branch without new code.
- **HUD:** one quest line under the compass while a quest is active, plus a short message when the objective changes or the quest ends. No journal screen.
- **Player-experience audit (renders, 2026-09-28):** Hollis (green cloak) stands near the notice board by the start point, so the request is the first conversation on offer. Accepting shows "The Missing Ring / Find out where the ring went." top right plus a one-time line at the bottom. At the forest edge the hoard reads as a small pile with a glint and a "Search" prompt, outside the midge trigger: standing there never starts the fight. Guarded, it shows the ring and gives nothing; after the fight it offers the ring; with Wenna's stone the trade drops it and the midges stay. Hollis recognises the ring whether or not you took the quest. Given back: a lamp by Hollis's door (subtle but visible from the plaza). Kept: a third, larger note on the board and the LOST text when you read it; the quest line disappears either way. ## M10 WorldEventDirector (2026-09-28)

- **The director only decides.** `EventDirector` (pure, static, flag store passed in) decides whether an event is eligible, which one fires, which variant, and writes the start flags plus bookkeeping. How an event plays out belongs to existing systems: dialogue data (EQUALS on `event.<id>.variant`), speaker-less conversations on `Interactable`s, `StateToggle`s. It never runs dialogue, starts combat or tracks objectives. No autoload: `EventHost` (a node in the region) is the only glue.
- **Data:** `EventData` (`region`, `weight`, `conditions` = `DialogueCondition`s, `repeat` ONCE/COOLDOWN, `cooldown`, `start` = SET_FLAG consequences, `announcement`, `variants`) and `EventVariant` (`id`, `weight`, `conditions`, `start`) in `scripts/events/data/`, instances in `data/events/`. `validate()` rejects zero weights, a bad cooldown/repeat pairing, non-flag consequences, events that change nothing, and variant lists where every variant is conditional. Content that ends an event writes `event.<id>.resolved` by convention; the director doesn't need it (ONCE covers the slice).
- **Opportunity, not time.** `event.director.opportunity` counts chances to evaluate. In M10 `EventHost` creates one when the player enters a *different* `EventRegion` than last time (`event.director.last_region`, so reloads and spawning in place don't count) at a safe moment (player input enabled = not in combat or dialogue; camera not cinematic). Unsafe entries are skipped, not queued. Cooldowns count opportunities; a later source (rest, day/night) can call `evaluate` without touching selection.
- **Spam control:** ONCE events never refire; COOLDOWN events wait `cooldown` opportunities; director-wide `GAP` = 1 (the opportunity right after any event is quiet); one evaluation per region change. Events never interrupt: they change the world and show one HUD line with the discovery sound.
- **Determinism:** each pick seeds a fresh RNG from `hash([seed, opportunity, region or event id, salt])`, with `event.director.seed` written once (random, or `--seed=` in debug runs). No RNG state is saved; the same flags always give the same event and variant, so reloading can't reroll. Tests use fixed seeds only (at opportunity 1: seed 1 = sleeping spirit, 3 = magical leak, 8 with the shrine awake = world anomaly).
- **Everything is flags**, so M12 save/load needs nothing extra. The director applies SET_FLAG with the same one-line rule as `DialogueRunner` (empty value = true); kept as a two-line duplicate rather than refactoring the runner.
- **Slice content:** *The Glowing Fish* (village, after `discovered.abandoned_camp`, ONCE; variants magical leak / sleeping spirit / world anomaly, the last only after the shrine wakes). Fish glow in the well and in a bucket beside it; Wenna explains per variant; the bucket offers "Release them into the pond", which empties the well, lights the pond (`world.pond_glows`) and resolves it. *Night-berries* (forest, needs `world.berries_picked`, which the four `PickBerries` interactables now set via `sets_flag`; COOLDOWN 3) resets all bushes to pickable. F8 (`debug_trigger_event`, debug builds) evaluates the current region now, ignoring the gap but never the conditions.
- **Player-experience audit (renders, 2026-09-28):** Coming back to the village shows "Something is glowing in the village well."; the well glows warm gold and a bucket of glowing fish sits beside it with a "Look in the bucket" prompt. Wenna's variant lines read clearly; with the shrine awake, its teal well glow stays distinct from the gold bucket. Releasing the fish empties the well and scatters glowing fish across the pond, which persists after a reload. Berries: an empty bush after picking; after the event, "The night-berry bushes have fruited again." with berries and prompt back. Found and fixed: the bucket was a dark speck (glow now above the rim with a small light), the well light washed out the fish (bigger fish, dimmer light), and the lit pond was a flat orange slab (now scattered glowing fish). Weak spots: the fish in the well are still small at normal zoom (the announcement and bucket carry the event); the pond glow is subtle and partly hidden by a tree from the south; Wenna can offer up to six replies at once.

## M12 Save/load (2026-09-28)

- **Save only what's authoritative.** `GameState.flags` (quests, dialogue facts, events and director bookkeeping, discoveries, encounters, guild upgrade), player position, player health (it lives on the Player node and carries between fights). Everything else is rebuilt: StateToggles, InteriorZone cutaway + camera mask, quest HUD, idle enemies, event presentation. Not saved: fights, conversations, cinematics, HUD state, camera pose, player facing. There is no second copy of world state; a new persistent fact is a new flag.
- **ConfigFile, not JSON.** JSON turns ints into floats, and `EventDirector` checks `last is int` for the gap and cooldowns, so events would refire after a load. ConfigFile keeps bool/int/float/String/Vector3, is readable text and is already used (`user://audio.cfg`). Not a `.tres`: loading a user-editable resource can pull in scripts. Flag keys are sorted before writing, so the same facts always give the same bytes. Flag values must be bool/int/float/String; anything else rejects the save.
- **Format:** `[save] version`, `[player] position, health`, `[state] flags`. Written to `<path>.tmp` and renamed over the save (replaces it in one step on Windows), so a failed write never leaves a half save. Unknown flag keys survive, unknown sections are ignored.
- **Versions:** newer than `SaveGame.VERSION` is refused; older goes through `SaveGame.migrations` (one step per version, kept inside SaveGame); an older version without a step is refused. A refused, corrupt or invalid save changes nothing (flags, world) and stays on disk; the HUD says why.
- **Load = the F5 path.** Replace `GameState.flags` wholesale (no `flag_changed`; the world is rebuilt anyway), then `_swap_world` with player position + health set before `add_child`; the camera rig snaps to the player in its `_ready`; the HUD binds before `add_child` and rebuilds its quest cache without announcing. Setting the position before the tree matters: the first physics step happens at the saved spot, so the default spawn never touches the village region, discovery zones or triggers.
- **No false event opportunity:** `event.director.last_region` is a flag, so the region reported on the first step after a load equals the saved one and `EventHost` returns early. Nothing in M10 changed. Known edge (same as F5 today): a region entry skipped during a cinematic doesn't update `last_region`, so a save made right there counts the region on load.
- **Interior:** nothing saved. The player is inside the `InteriorZone` from the first physics step; renders show frame 2 (the first drawn frame) already cut away with the camera settled, so no load fade.
- **UX:** one slot `user://save.cfg`; F9 quicksave in all builds ("Saved." / "Can't save right now."); autosave on window close when safe (otherwise the last save stays); continue on launch when a valid save exists. Saving is refused in combat, dialogue, cinematics and any world but `slice_region` (same safety rule as `EventHost.is_safe`). Debug: F10 load (refused mid-fight or mid-conversation), `--load`, `--fresh`, `--save-file=<abs>`. Shot runs, `--world` runs and tests (main isn't the current scene) never continue from the developer save. No title screen or New Game menu yet.
- **Player-experience audit (renders, 2026-09-28):** Loading feels like nothing happened, which is the goal: the village, the forest camp, the damaged room and the repaired room come back exactly as saved, with the quest line in place and no card, message or event. Inside the repaired guild the first drawn frame is already the warm cut-away room with Maren at the table. The Glowing Fish bucket still glows by the well after a load. Weak spots: no feedback on load (by design); `--fresh` or a new game overwrites the old save on the next save or close; pad players can only rely on autosave; the roof pull-in near buildings shows up in load shots too (existing backlog).
